# Gateway Package (`@navi/agent-gateway`) Implementation Plan — Phases 0+1

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A standalone, tested TypeScript package that drives Claude Code, Codex, and Gemini CLI through one normalized interface — streaming, permissions, resume, usage, and cross-backend agent spawning — proven by a terminal REPL before any UI exists.

**Architecture:** One `AgentBackend` interface, three adapters each using the backend's best native programmatic interface (Claude Agent SDK in-process; Codex app-server JSON-RPC over stdio; Gemini ACP over stdio). All output normalizes to a zod-validated `GatewayEvent` stream. Cross-backend multi-agent is a built-in MCP server exposing `spawn_agent` tools. Capabilities contract declares per-backend degradations honestly.

**Tech Stack:** Bun 1.2 workspaces, TypeScript, zod, `@anthropic-ai/claude-agent-sdk` (^0.3), `@openai/codex-sdk` (^0.139), `@agentclientprotocol/sdk` (Gemini ACP client), `@modelcontextprotocol/sdk` (spawn server), `bun test`.

**Spec:** `claude-code-local-ui/docs/superpowers/specs/2026-06-10-navi-rebuild-design.md` (old repo). Old working code to port from: `claude-code-local-ui/packages/navi-app/server/backends/`.

**Verified on this machine (2026-06-10):** bun 1.2.18, claude 2.1.170, codex-cli 0.128.0 (`codex app-server` ✓, `generate-ts` ✓), gemini 0.24.4 (`--experimental-acp` ✓).

```ts
// All variants share sessionId: z.string()
// text-delta:        { text: string }
// thinking-delta:    { text: string }
// tool-start:        { toolId: string; tool: string; input: unknown }
// tool-output:       { toolId: string; chunk: string }
// tool-end:          { toolId: string; result?: unknown; isError?: boolean }
// permission-request:{ requestId: string; tool: string; description: string; input: unknown;
//                      options: Array<"allow"|"allow-session"|"deny"> }
// usage:             { usage: UsageSchema }
// session-meta:      { backendSessionId?: string; model?: string; cwd?: string }
// agent-spawned:     { childSessionId: string; backend: string; task: string }
// error:             { message: string; detail?: unknown; fatal?: boolean }
// done:              { reason: "complete" | "cancelled" | "error" }
export const UsageSchema = z.object({
  inputTokens: z.number(), outputTokens: z.number(),
  cacheReadTokens: z.number().optional(), cacheWriteTokens: z.number().optional(),
  costUsd: z.number().optional(), model: z.string(), raw: z.unknown(),
});
export type GatewayEvent = z.infer<typeof GatewayEventSchema>;
export type PermissionDecision = "allow" | "allow-session" | "deny";
```

- [ ] **Step 3: Implement.** `types.ts`:

```ts
export type Capabilities = {
  streaming: boolean;
  thinkingStream: boolean;
  permissions: "callback" | "modes-only";
  resume: boolean;
  mcp: boolean;
  models: Array<{ id: string; label: string; default?: boolean }>;
};
export type DetectResult = { installed: boolean; authed: boolean; version?: string; fixHint?: string };
export type SessionOptions = {
  cwd: string; model?: string;
  permissionMode: "prompt" | "acceptEdits" | "acceptAll" | "readOnly";
  mcpServers?: McpServerConfig[];           // gateway injects its own spawn server here
  systemContext?: string;                    // skills index etc.
};
export type UserInput = { text: string };
export interface AgentSession {
  readonly id: string;                       // gateway-assigned
  send(input: UserInput): AsyncIterable<GatewayEvent>;
  respondToPermission(requestId: string, decision: PermissionDecision): void;
  cancel(): Promise<void>;
}
export interface AgentBackend {
  readonly id: "claude" | "codex" | "gemini";
  capabilities(): Capabilities;
  detect(): Promise<DetectResult>;
  createSession(opts: SessionOptions): AgentSession;
  resumeSession(backendSessionId: string, opts: SessionOptions): AgentSession;
}
```

`registry.ts`: Map-based registry, `register/get/getAll/detectInstalled`. `detectInstalled()` calls each backend's `detect()` lazily and **caches the result** (`refresh: true` option to re-probe) — REPL/server startup probes each CLI at most once. No singletons exported pre-wired — caller constructs (`createDefaultRegistry()` added in Task 9).
